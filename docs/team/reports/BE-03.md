## Changed behaviour

- **Start-up safety (pilot server only).** With `ALLOW_SIGNUP=false` the server refuses to start if
  `JWT_SECRET` is an example value or shorter than 32 characters, or `PILOT_ACCOUNTS` is empty. It warns about
  sessions under an hour and Claude without a daily limit. Development machines (sign-up open) are unaffected.
- **`GET /api/health`** (public): `status`, `database`, `version`, `commit`, `evidence_retrieval: "disabled"`.
  Returns 503 if the database can't be reached. No settings, users or keys.
- **`uv run python -m app.backup create|check|restore`**: SQLite online backup + photos + manifest with an
  integrity check; keeps the newest N; a backup folder only appears once complete; restore refuses to
  overwrite without `--force`, and with `--force` moves current data aside instead of deleting it.
- `.gitignore`: `backups/` and `*.before-restore-*` (they contain testers' records).
- `docs/team/HOSTING.md`: Windows PC + Tailscale Funnel runbook, nightly backups, restore rehearsal, update
  and rollback, mobile API URL, release record.

## Schema / upgrade evidence

`tests/test_operations.py::test_database_from_before_pilot_accounts_upgrades_and_users_still_log_in` builds a
`user` table exactly as it was at `dfd5df0`, runs start-up's `create_all` + `add_missing_columns`, checks the
two BE-02 columns are added (and a second run adds nothing), then logs in and calls `/api/me` as the old user.
