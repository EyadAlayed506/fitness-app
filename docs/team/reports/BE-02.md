## Changed behaviour

- `ALLOW_SIGNUP` setting (default `true`, so local development and existing tests are unchanged). With
  `false`, sign-up returns `403 Sign-up is closed for this pilot`.
- `uv run python -m app.pilot_accounts [--dry-run]` makes the accounts match `PILOT_ACCOUNTS` in the server
  `.env`: creates, re-enables, changes passwords, and disables unlisted accounts. Never deletes data, never
  prints passwords. Runbook: [ACCOUNTS.md](../ACCOUNTS.md).
- Revocation: `User.disabled_at` and `User.token_version` (both nullable, so existing databases gain them on
  start-up through `add_missing_columns`). Login tokens carry `ver`. A disabled user, or a token older than
  the user's current version, gets the normal `401 Not logged in or session expired`. Tokens issued before
  this change (no `ver`) keep working.
- Disabled accounts can't log in: `403 This account no longer has access to the pilot`.

No mobile change is needed: the app already shows `detail` messages and handles 401 as "session expired".
